# 설치본 기반 건물·식물 카탈로그 — 설계안

상태: 2026-10-01 사용자 진행 요청에 따라 초기 건물 33개·식물 22종 연결을 구현했다. [구현 기록](../../LIVE_CATALOG_IMPLEMENTATION.md) 참고. 나머지 건물 확장과 실제 게임에서의 사용성 확인은 사용자 피드백을 따른다.

## 1. 목적과 접근

사용자가 예시 건물 대신 실제 게임의 이름·크기·방향으로 작은 다층 청사진을 만들어 보고, 게임에서 따라 지을 때의 사용감을 확인한다. 농지·과수원·조림지와 자원 파밍도 도시 계획에 포함되므로 작물·관목·나무를 건물과 같은 청사진에 배치한다. 기능 확장보다 데이터의 신뢰성을 우선한다.

설치본 JSON을 재현 가능한 방법으로 읽어 정적 카탈로그를 만든다. 웹은 생성된 JSON만 사용하며 실행할 때 Steam이나 게임 프로세스가 필요하지 않다. 위키는 교차 확인용으로 사용하고 설치본과 다른 내용을 조용히 섞지 않는다.

대안으로 위키 수작업 입력은 간단하지만 버전·출입구·점유 정보가 부족하고, 게임 모델 전체 추출은 현재 목표에 불필요하다. 설치본에서 필요한 사실 데이터만 추출하고 단순한 자체 도형으로 표시하는 방식을 선택한다.

## 3. 데이터셋과 경계

역할은 세 가지로 나눈다. 별도 서버·DB·플러그인 체계는 추가하지 않는다.

1. **로컬 추출 도구:** 명시한 게임 설치 경로의 버전·ZIP 파일만 읽는다. 원본을 수정하거나 게임을 실행하지 않는다. ZIP 전체를 저장소에 풀거나 게임 이미지·모델·번역 설명문을 복사하지 않는다.
2. **정적 원본 카탈로그:** 모든 건물 및 식물 정의의 필요한 필드와 진영 컬렉션을 수록한다. 이름은 한국어와 영어 표시명만 수록한다. 누락된 한국어 이름은 영어 이름, 그마저 없으면 TemplateName으로 대체하고 누락 목록을 남긴다.
3. **웹 표시 목록:** 원본 카탈로그 중 이번에 확인한 종류만 활성화한다. 표시 도형·색·표시 지원 여부는 원본 사실 데이터와 별도 설정으로 둔다.

카탈로그에는 다음을 보존한다.

- 데이터 형식 버전, 게임 버전, build ID, 입력 파일 해시, 각 항목의 ZIP 내부 경로.
- 원본 TemplateName, 진영 컬렉션 소속, 메뉴 분류·순서, 표시명 키와 이름.
- `BlockObjectSpec`의 원본 Size, Blocks 배열, Entrance, BaseZ, Flippable 및 관련 플래그.
- 계단 등 경로 오브젝트의 연결 좌표 정보. 미해석 필드는 원본 의미 그대로 보관하고 UI가 임의로 소비하지 않는다.
- 건물·작물·관목·나무 구분. 식물의 식재 작업 그룹, 성장 시간, 수확·벌목·반복 채집 정의, 자원 ID와 한국어 이름, 토양·수분·침수·건조 환경 조건. 초기 성장과 반복 채집 주기를 하나의 생산 주기로 합치지 않는다.
- 데이터 추출 상태와 웹 표시 지원 상태를 구분한다. 데이터가 있다고 해서 배치 규칙까지 지원한다는 뜻은 아니다.

출력은 정렬과 구조가 일정한 JSON으로 만들어 같은 입력의 불필요한 diff를 방지한다. 필수 파일 손상, 중복 식별자, 끊어진 컬렉션 참조는 오류로 보고 기존 생성물을 부분 덮어쓰기하지 않는다. 저장소에는 개인 Steam 계정 정보나 전체 설치 manifest를 넣지 않는다.

## 4. 첫 웹 연결 범위

기존 건물·구조물 33개와 식물 22개를 합쳐 총 55개 TemplateName 항목을 목표로 한다. 공통 항목을 각 진영에 포함하면 Folktails 31개, IronTeeth 30개다. 건물·구조물 부분은 공통 Path 1개와 진영별 정의를 구분한 33개이며, 한 진영에서는 17개를 사용할 수 있다.

- **주거 8개:** Folktails의 Lodge, MiniLodge, DoubleLodge, TripleLodge; IronTeeth의 Barrack, LargeBarrack, Rowhouse, LargeRowhouse.
- **기본 구조물 9개:** 공통 Path; 두 진영 각각 Stairs, Platform, DoublePlatform, TriplePlatform.
- **지상 저장시설 16개:** 두 진영 각각 Small/Medium/LargeWarehouse, Small/Medium/LargeTank; Folktails의 Small/LargePile, IronTeeth의 Small/LargeIndustrialPile.
- **공통 식물 5종:** BlueberryBush, Birch, Succulent, Oak, Pine.
- **Folktails 식물 9종:** Dandelion, Carrot, Cattail, Potato, Spadderdock, Sunflower, Wheat, ChestnutTree, Maple.
- **IronTeeth 식물 8종:** CoffeeBush, Canola, Cassava, Corn, Eggplant, Kohlrabi, Soybean, Mangrove.

라이브러리에서 식물을 건물과 구별하고, 한국어 이름·점유 크기·자원 종류·생육 조건을 확인할 수 있게 한다. 식물도 별도 영역 메모가 아니라 기존 배치처럼 고유 ID와 좌표를 가진 청사진 항목으로 저장·복제·삭제한다. 단순한 작물 덩어리·관목·나무 도형을 사용하며 성체 기준의 공간 계획임을 표시한다. 외부 에이전트도 같은 데이터를 읽어 농지와 조림지를 수정할 수 있어야 한다.

이번에는 기존 타일 단위 배치 흐름을 재사용한다. 넓은 영역을 한 번에 심는 브러시, 성장 애니메이션, 관개·수심·수확 주기 시뮬레이션, 생산량·인구 부양 계산은 추가하지 않는다. 농가·수생 농가·채집소·벌목소·숲지기 등 작업 건물은 원본 전체 카탈로그에는 확보하지만, 이번 변경에서 활성 건물 목록까지 자동으로 확장하지는 않는다.

지하 저장소, 나선 계단, 금속 플랫폼, 돌출 구조물, 동력축, 번식시설 등은 전체 데이터에는 포함하되 이번 활성 목록에는 넣지 않는다. 미지원 정의를 일반 상자로 대체하여 사용 가능한 것처럼 노출하지 않는다.

## 5. 좌표·표시·검증 정책

기존 웹 청사진의 X·Z 바닥 / Y 높이 규약은 유지한다. 원본의 격자 크기는 X·Y 바닥 / Z 높이이므로 원본과 웹 좌표를 혼용하지 않는다. 원본 좌표는 보존하고, 웹용 좌표는 별도 변환 단계에서 만든다.

- 크기는 원본 `(X, Y, Z)`를 웹의 `(너비 X, 높이 Y, 깊이 Z) = (X, Z, Y)`로 변환한다.
- 출입구와 계단 방향은 원본 좌표에서 함께 변환한다. 회전할 때 몸체·점유 영역·출입구 표시가 같은 변환을 거친다. 기존 예시 모델의 정면 `+Z`를 실제 건물의 정면이라고 가정하지 않는다.
- 표시 모델의 높이, 점유 범위, 적층 가능한 표면을 구분한다. 계단을 높이 2짜리 계단으로 늘리거나 길을 높이 1짜리 벽돌로 표시하지 않는다.
- `Blocks` 배열의 인덱스 순서와 각 플래그의 런타임 의미는 검증 후에만 공간 계산에 사용한다. 추출 자체는 원본 순서를 보존하므로 해석을 기다릴 필요가 없다.
- 기존 직육면체 겹침 검사는 보수적인 검사로 유지한다. 단, 표시 형상과 예약된 점유 범위를 구분하여 길·계단을 잘못된 높이로 렌더링하지 않는다. 플랫폼 내부 통과 등 게임에서 가능한 조합을 막을 수 있음을 UI에 명시한다.
- 지지 구조, 출입 가능성, 전력·물 연결 등 전체 게임 건설 판정은 이번에 구현하지 않는다. 검사 통과를 게임 내 건설 가능으로 표시하지 않는다.
- 자동 표면 스냅은 검증된 적층 표면에만 연결한다. 모든 모델의 바운딩 박스 윗면을 지붕으로 간주하지 않는다. 지정 높이 배치는 기존 Shift 조작을 유지한다.
- 식물은 적층 표면을 제공하지 않는다. 자동 배치는 바닥을 기준으로 하고 건물·플랫폼 윗면을 토양으로 간주해 식물을 자동 스냅하지 않는다. 기존 Shift 지정 높이 조작은 다층 농지의 계획 배치에도 유지한다. 토양 모델이 없으므로 높이만으로 식재 가능 여부를 판정하거나 임의로 0층에 제한하지 않고, 토양·지지 조건은 미검증으로 표시한다.
- 수생·건조 환경 식물도 배치 계획 대상으로 노출하되 환경 조건을 표시한다. 평면에 배치했다는 이유만으로 해당 위치에서 실제로 재배 가능하다고 판정하지 않는다. 수면·토양 환경 구성은 이번 단계에 만들지 않는다.
- 좌우 반전 가능한 원본 속성은 보존하되 반전 편집 기능은 이번 범위에 추가하지 않는다. 기본 방향과 90도 회전을 지원한다.

원본 `MapSizeSpec`의 최대 지형 높이 22·추가 높이 10도 카탈로그 메타데이터에 기록한다. 이 값만으로 건물 바닥/꼭대기 경계나 평탄화 기준 고도를 확정하지 않는다. **현재 32×32 격자와 임시 Y=12 편집 제한은 이번 데이터 연결에서 유지하고, 게임 높이 판정에 맞추는 변경은 별도로 다룬다.** UI와 문서에서 이를 게임의 최대 높이라고 표현하지 않는다.

## 6. 기존 청사진 보존

- 새 실제 카탈로그는 기존 `layout-demo`와 다른 프로필 및 게임 버전 식별자를 사용한다. 기존 `demo-*` 식별자를 실제 건물로 치환하거나 크기를 바꾸지 않는다.
- 브라우저 저장 키를 카탈로그 프로필·진영별로 분리한다. 기존 저장 키는 지우거나 덮어쓰지 않는다.
- 신규 사용은 실제 카탈로그로 시작한다. 기존 예시 작업은 간단한 `실제 게임 / 예시` 전환으로 다시 열 수 있고 JSON 내보내기도 유지한다.
- 저장된 JSON에는 카탈로그 프로필과 해당 데이터 버전을 명시한다. 예시와 실제 오브젝트를 한 청사진에 섞지 않는다. 실제 건물과 식물은 같은 배치 목록에 저장하며, 서로 다른 진영의 전용 식물이 섞인 가져오기도 거부한다.
- 파일 열기는 읽기·형식 검사·버전 및 진영 검사·공간 검사를 먼저 수행한다. 실패하면 현재 설계와 저장본을 유지한다. 알 수 없는 종류나 버전을 임의로 최신 정의에 연결하지 않는다.
- WASD 속도 등 보기 설정은 계속 청사진과 분리한다.

실제 카탈로그용 새 청사진은 비어 있는 상태로 시작한다. 기존 예시 배치를 실제 크기에 억지로 맞춰 자동 이전하지 않는다.

## 7. 완료 기준

1. 설치본 버전과 입력 해시로 추출 결과를 추적할 수 있고, 동일 입력을 재추출하면 동일 결과가 나온다.
2. 전체 정의·진영 참조·번역 연결과 제외 이유를 검사한다. 게임 원본, 설치 manifest, 바이너리·그래픽 원본이 저장소에 들어가지 않는다.
3. 원본 샘플의 치수·출입구·층 높이를 직접 대조하는 테스트가 있다. 파서의 계산 결과를 그대로 기대값으로 재사용하지 않는다.
4. 진영을 바꾸면 Folktails 31개, IronTeeth 30개 항목이 보이고 다른 진영의 전용 건물·식물을 새로 배치할 수 없다. 공통 식물은 양쪽에서 사용할 수 있다.
5. 1·2·3층 플랫폼, 계단, 출입구 높이가 다른 주거와 저장시설을 배치·회전·관찰하고 JSON 왕복이 가능하다.
6. 예시 저장본과 실제 저장본이 서로 영향을 주지 않고, 실패한 가져오기가 현재 작업을 덮어쓰지 않는다.
7. 미지원 규칙과 임시 편집 제한이 화면에서 구별된다. 기존 배치·탐색·속도 조절 테스트도 유지한다.
8. 주거·저장시설 옆에 작물·관목·나무를 함께 배치한 청사진을 저장하고 다시 열어도 식물의 종류·좌표·ID가 유지된다. 건물 윗면으로의 자동 식재 스냅과 식물 위 자동 적층을 막고, 점유 겹침을 검사한다. Shift 지정 높이는 계획 좌표로 저장하되 토양·지지 조건 검증과 구별한다.
9. 식물의 한국어 이름, 바닥 크기와 성체 점유 높이, 수확 자원 및 환경 조건을 원본과 대조한다. 수생 식물의 노출과 조건 경고, 초기 성장과 반복 수확의 구분, Oak/Maple 식별자 충돌 방지를 검증한다.

검증은 작은 다층 배치를 대상으로 한다. 거대한 도시의 성능 최적화, 모든 건물 활성화, 세이브 연동, AI 도구/API 추가는 별도 단계다.
