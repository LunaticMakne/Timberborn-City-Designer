# 청사진 설계 데이터

현재 화면의 저장 형식을 설명한다. 실제 Timberborn 세이브 형식과는 관계없는 청사진 JSON이다.

## 예시

```json
{
  "schemaVersion": 1,
  "catalogProfile": "timberborn-1.1.2.4",
  "catalogRevision": "EA79A4A818D1268CE2D7B26F70F806196B7A046924A245A761E0B387E54A67FC",
  "name": "첫 번째 청사진",
  "faction": "folktails",
  "gridSize": 128,
  "objects": [
    {
      "id": "house-001",
      "objectType": "Lodge.Folktails",
      "position": { "x": 9, "y": 0, "z": 10 },
      "rotation": 90
    }
  ]
}
```

## 의미와 좌표

- `catalogProfile: "layout-demo"`는 치수가 미검증인 예시 라이브러리를 사용한다는 뜻이다. 실제 게임 데이터라는 의미가 아니다.
- 실제 카탈로그는 `catalogProfile: "timberborn-1.1.2.4"`와 `catalogRevision`(Blueprints.zip SHA-256)을 함께 요구한다. 알 수 없는 프로필/리비전, 진영에 없는 종류, 예시와 실제 종류의 혼합을 거부한다. 기존 예시 JSON은 리비전 없이 그대로 읽는다.
- `faction`은 `folktails` 또는 `iron-teeth`다. 실제 목록은 공통 정의와 선택 진영 정의를 합친다. 데이터 세트·진영별 브라우저 저장을 분리하며 기존 `layout-v1` 저장 키는 유지한다.
- `id`는 배치별로 유일하다. 오브젝트를 이동·회전할 때 유지하고, 새로 만들거나 복제할 때 새 식별자를 준다.
- `objectType`은 실제 카탈로그의 TemplateName이다. 예시는 `src/data.ts`의 `demo-*` 식별자를 사용한다. 활성 목록은 `src/generated/active-catalog.json`, 전체 조사 자료는 `data/game-catalog.json`이다. 전체 자료의 비활성 종류는 아직 불러올 수 없다. 런타임 정의의 `size`는 `[X 방향 너비, Y 방향 높이, Z 방향 깊이]`다.
- 바닥의 두 축은 X, Z이고 위쪽 높이가 Y다. 평평한 바닥은 Y = 0이며 단위는 타일이다.
- `position`은 회전 후 점유 직육면체의 최소 X·Y·Z 모서리다. 웹 렌더링의 화면 중심 보정은 데이터에 넣지 않는다.
- `rotation`은 위에서 보았을 때 시계 방향으로 0, 90, 180, 270도다. 예시 건물 정면은 +Z다. 초기 실제 건물 입구와 계단 상승 방향은 -Z이며 원본 XY 수평/Z 높이를 웹 XZ 수평/Y 높이로 변환했다. 90도에서는 가로와 깊이를 바꾼다. 원본 입구는 점유 범위 바깥 칸일 수 있고, 높이는 건물 시작 높이에 상대적이다. 식물의 회전은 저장되지만 재배 방향을 의미하지 않는다.
- `gridSize`는 정사각 바닥 한 변의 타일 수이며 4~256의 정수다. 새 실제 청사진의 기본값은 128, 기존 예시 기본값은 32다. UI의 빠른 선택은 32·64·128·256이며 JSON에서 불러온 다른 크기도 유지한다. 배치 위치는 X·Z = 0~`gridSize - 1`, Y = 0~12의 정수다. 회전된 점유 공간이 다른 오브젝트와 겹치거나 X·Z 방향 끝이 격자 밖으로 나가면 새 배치·변경·불러오기를 막는다. 면만 닿는 인접 배치와 정확히 윗면 위에 쌓는 배치는 겹침으로 보지 않는다.
- 카메라, 선택 항목, 현재 배치 높이, 층 숨김은 청사진 파일에 포함하지 않는다.

가로·세로의 기본값과 범위는 설치본 1.1.2.4의 `Configurations/MapSize.blueprint.json`에서 확인했다(`data/game-catalog.json`의 `mapSize`에도 보관). 직사각형 맵과 지형은 아직 지원하지 않는다. 시작 높이 0–12는 여전히 임시 편집기 한도이며 게임 높이 한도로 해석하지 않는다.

바닥 크기를 변경해도 오브젝트 좌표·ID·회전은 그대로다. 축소 시 회전된 점유 공간이 새 바닥을 벗어나면 변경을 거부한다. 크기 변경은 실행 취소/다시 실행·자동 저장·JSON 저장에 포함되며 기존 32칸 파일과 브라우저 저장본을 자동 확장하지 않는다. 변경 시 카메라는 새 바닥을 전체 보기로 맞춘다. 청사진 최대 10,000개 한도는 새 배치에서도 검사하며 초과하는 드래그는 전체 거부한다.

식물도 같은 `objects` 배열에 배치한다. 예를 들어 `Carrot`, `Oak`, `Maple`은 서로 다른 종류이며, Oak의 과거 호환 이름을 Maple의 별칭으로 사용하지 않는다. 재배 조건·성장/수확/채집 정보는 정의의 `plant`에 보관하며 청사진마다 복제하지 않는다. `block`, `path`, `navigation`은 원본 좌표계의 필드를 그대로 유지한 자료다. 웹 좌표나 완성된 게임 규칙으로 오해하지 않는다.

## 구역 센터와 길 연결

`DistrictCenter.Folktails` / `DistrictCenter.IronTeeth`는 구역 센터(마을 회관)다. 두 정의 모두 웹 기준 `[3, 5, 3]`, 로컬 입구 `(1, 0, -1)`이다. 전체 자료는 바뀌지 않았고 같은 원본 리비전에서 활성 종류만 55→57개로 늘렸다. 기존 실제 청사진은 그대로 읽는다.

연결 상태는 청사진으로부터 매번 계산하며 JSON에는 저장하지 않는다. `src/connectivity.ts`의 `roadConnectivity`가 오브젝트 ID별 상태와 유효 센터 수를 반환한다. 원본 `navigation.EdgeGroups`의 `IsPath` 간선을 웹 좌표로 회전·변환하고 `IsTwoWay`를 반영한다. 외부 칸으로 나가는 간선은 상대 노드의 반대 방향 간선이 있어야 연결한다. 노드가 없는 빈 칸, 계단 옆면, 높이가 다른 길을 연결하지 않는다. 센터의 `path.MainPathCoordinates`들을 시작점으로 탐색한다.

건물은 입구 칸에 도달 가능한 노드가 있고 그 노드에서 출입문 안쪽으로 향하는 간선이 있어야 연결로 표시한다. 현재 활성 정의의 모든 입구가 로컬 -Z 방향이라는 전제를 사용한다. 새 종류를 추가할 때 이 전제도 검토해야 한다. 플랫폼/지붕은 명시적인 길 없이 경로가 되지 않는다. 식물처럼 입구가 없는 종류는 검사 대상이 아니다.

상태는 `source`, `connected`, `disconnected`, `no-center`, `invalid`다. 여러 센터 중 하나에 연결되면 `connected`이며 구역 소속을 지정하지 않는다. 숨긴 층도 계산하지만 겹침·경계 오류 항목은 제외한다. 지지·지형·이동 거리·게임 내 통행 규칙은 별도 검증 범위다.

## 에이전트와 주고받기

드래그 영역 설치도 기존 `objects` 배열에 독립 항목을 추가한다. 영역 전용 스키마나 영구 그룹은 만들지 않는다. 각 배치에 새 ID를 부여하며 하나의 실행 취소 이력으로 저장한다. 전체 후보를 먼저 검사하고, 하나라도 겹침·경계 문제가 있으면 아무것도 추가하지 않는다. 높이는 시작 표면(Shift 시작 시 선택 높이)에 고정하고, 회전된 너비·깊이 간격으로 시작점에서 끝점 방향으로 채운다. 미리보기의 박스는 실제 도형이 아닌 예약 점유 공간이다.

1. 화면에서 **청사진 저장**을 눌러 JSON을 저장한다.
2. 에이전트는 `objects`에서 식별자·높이·좌표 범위 등으로 필요한 항목을 찾는다.
3. 기존 항목의 식별자를 유지하며 필요한 값만 수정한다.
4. 화면의 **열기**로 수정한 JSON을 불러와 결과를 확인한다.

현재 자동 파일 감시나 부분 조회 API는 없다. 화면은 전체 JSON을 읽고 쓰며, 부분 조회는 에이전트가 파일을 읽을 때 수행한다. 별도 AI 대화창과 서비스 연결도 아직 없다.

파일을 불러올 때는 지원하는 형식·종류·좌표 값·중복 식별자를 확인한 뒤, `src/placement.ts`의 공통 검사로 겹침과 격자 경계를 확인한다. 문제가 있는 파일이면 현재 설계를 유지하고 이유를 표시한다. 이전 버전의 브라우저 저장본은 복구할 수 있도록 그대로 열고, 문제가 있는 항목을 빨간 테두리로 표시한다.

점유 공간은 카탈로그 `size`에 회전을 적용한 직육면체다. 숨긴 층의 오브젝트도 검사 대상이며, 기존 항목을 편집할 때는 같은 `id`인 자기 자신을 제외한다. 플랫폼 내부의 빈 공간 등 특수 규칙은 아직 표현하지 않는다. 이 검사는 공간의 겹침만 다루며, 게임에서 실제로 지지되거나 출입 가능한지 등을 보장하지 않는다.

층 숨김은 `position.y <= 선택 높이`인 오브젝트 전체를 표시한다. 여러 층 높이의 건물을 중간에서 자르는 단면 보기는 아직 지원하지 않는다.

마우스 배치는 화면에 보이는 건물·플랫폼 등의 윗면에 맞춰 실제 높이를 `position.y`에 저장한다. 자동 배치에서 윗면을 가리키지 않으면 바닥 0층을 사용하며, 표시 높이가 배치 높이의 하한이 되지 않는다. Shift를 누를 때만 선택한 기준 높이의 평면에 고정한다. 복제는 원본의 종류·방향을 사용하고 실제 위치와 높이는 새 배치 시 정한다. 표면 스냅은 좌표를 정하는 보조 기능이며 게임의 지지·충돌 규칙 검증과는 별개다.

실제 카탈로그에서는 확인된 균일 상단을 가진 주거·창고·플랫폼·산업용 더미만 스냅을 지원한다. 식물은 스냅 표면이 아니며, 식물 배치도 자동으로 지붕에 올라가지 않는다. Shift로 지정한 식물 높이는 계획 토양 위치일 뿐 재배 가능 판정이 아니다. 길의 표시 높이 0.12 / 점유 높이 1, 계단의 상승 높이 1 / 점유 높이 2도 구분한다. 현재 전체 박스 검사는 일부 게임상 유효한 배치를 보수적으로 거절할 수 있다.
